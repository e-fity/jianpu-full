## 3. 统一歌库设计

### 3.1 目录与来源

| 目录 | 内容 | 谁写 |
|---|---|---|
| `scores/` | **唯一歌库**：`<id>.json`，一律 `jianpu-score-json` 格式 | `import_scores.py`（57 首）+ `game_chart.py`（识别曲目） |
| `scores/manifest.json` | 导入清单：id、文件名、sha256、来源 URL、导入时间 | `import_scores.py` |
| `out/` | 识别产物：`_notes.json` + `_overlay.png`（审阅、改框、对照图仍靠它） | `/api/convert` |
| `web/audio/` | 两件真实采样 wav | `import_scores.py` |
| `视频/` | 成品 mp4 | 不变 |

### 3.2 ID 规则

- 网站 57 首**保留原 id**（`china`、`longhui`、`duqing`…），这样播放器里逐曲特判、默认音色表全部沿用，零改动。
- 识别曲目用上传文件名词干（如 `42`、`my_song`），入库时若与已有 id 冲突则加 `-2`。

**为什么 id 不能改**：播放器的 `routeFor()` 用字符串比较决定播放路线，例如 `longhui` 要"主歌 0–16 小节播两遍（早/晚）、副歌两遍、尾声一遍"，`borrow` 要"16–37 小节反复一次"。这些规则只认 id；谱面文件里并没有反复展开后的数据（只有一遍）。改了 id 或换成本地曲名，分支不触发 → 整首只播一遍，时长直接少一半。

| 分支 | 曲目 | 规则要点 |
|---|---|---|
| 手写路线 | mother | 全曲跑两遍，标"第一段/第二段" |
| 手写路线 | borrow | 0–15 → 16–37 → 38–40 → **16–37 反复** → 41–47 |
| 手写路线 | longhui | 0–16 两遍（早/晚）→ 17–25 两遍 → 26–30 尾声 |
| 手写路线 | rain | 顺序播，按小节 `region` 标段名 |
| 手写路线 | duqing | 按谱面 `form.playback_order` 播，重复段标"反复" |
| 手写路线 | dang | 主歌两段 + 副歌两遍 |
| 手写路线 | tiexue | 前奏 → 对唱 → 第一遍结尾 → **对唱反复** → 第二遍结尾 → 尾奏 |
| 手写路线 | shanghai | 前奏 → 第一段 → 第二段（两遍）→ 第三段 → 尾声 |
| 通用表 | 其余 67 首 | 按 `form.source_order` 顺序一遍过 |
| 兜底 | china | 顺序播放，带分段标题 |

> 这套逻辑只存在于**网站的** `game.js` 里；本地 `D:\Letter piano jk` 没有等价物（现有视频本来就是一遍过），所以必须原样搬过来、并保留 id。

### 3.3 转谱时补的本地字段

`scores/<id>.json` 顶层加一个 `x_local` 块（播放器不读，本地用）：

```json
"x_local": {
  "origin": "recognized",              // recognized | imported
  "notes_json": "out/42_notes.json",   // 溯源
  "notes_sha256": "…",                 // 判断是否需要重新转谱
  "overlay": "42_overlay.png",
  "instrument": "piano",               // 默认主音色
  "accompaniment": ["cello"],          // 默认伴奏
  "style": "lyrical",
  "created": "2026-10-19T18:30:00+08:00"
}
```

### 3.4 索引接口

`GET /api/game/songs` 返回合并列表（按「网站顺序 + 本地新增」）：

```json
{"songs": [
  {"id": "china", "title": "我的中国心", "key": "1=♭E", "tonic_midi": 63,
   "tempo_qpm": 100, "meter": "4/4", "notes": 262, "duration": 287.6,
```

## 5. 转谱规则（notes → jianpu-score-json）

只用于识别曲目（57 首是原生格式，不转）。

| 本地字段 | 目标字段 | 规则 |
|---|---|---|
| `title` | `document.title` | 原样 |
| `key` `"1=Ab"` | `musical_setup.key_mark`=`"1=A♭"` + `tonic_midi` | 规范成 ♭ 号；根音落第 4 八度：C4=60、♭E4=63、♭A4=68、♭B4=70、B4=71 |
| `meter` `"4/4"` | `beats / beat_unit / printed` | 直接拆 |
| `tempo_qpm` | 同名 | 原样（13 首是默认 100，可在曲库页改） |
| `lines[].notes[]` | `measures[].events[]` | 按 `(line, index)` 顺序；**跨行连续累加**，满一小节才切 |
| `n=0` | `{"r": true, "q": q}` | 休止占事件序号 |
| `n / o` | `event.n / event.o` | `-1/0/1` 为低/中/高，`-2/2/3` 原样 |
| `letter` + `shift` | `keyboard.key / modifier` | `LSHIFT`→`left_shift`，`RSHIFT`→`right_shift` |
| `q` | `event.q` | 不变（四分音符 = 1） |
| `lyric` | `lyrics.by_measure_and_pass[m]["main"]` | 按 `event_index` 对齐，一字多音写多个序号 |
| 元信息 | `x_local` | §3.3 |

补充规则：

1. **跨小节长音**：切成两个事件 + `connections:[{"type":"tie","from":"m003:4","to":"m004:1"}]`，播放器会把时值合并回来。
2. **歌词只有第一段**（本地数据现状），遍次固定 `"main"`；"下一句"字幕因此可用。
3. **调号统一**：`Ab/Eb/Bb` 写成 `A♭/E♭/B♭`，同时给 `tonic_midi`，否则游戏整体移调。

### 5.1 验收断言（`test_game_chart.py`）

- 非休止事件数 == `counts.letters`（22 首逐首）。
- 总时长 ≈ `sum(q) × 60 / tempo`，与 `make_video.py` 时间轴差 < 0.01 s。
- 每个事件 `keyboard.key` == 源 `letter`。
- 每小节 `sum(q)` == `beats`（末小节除外）。
- 22 首全部能通过 `GET /api/game/chart/<id>` 返回且可解析。

## 6. 音频方案（要求 2 的核心）

### 6.1 为什么不能直接"复制声音"

网站的音色不是音频文件，是**运行时用振荡器 + 滤波 + 包络合成的参数**（`INSTRUMENTS` 里 40 多套参数），伴奏也是现场按小节推和弦。所以要拿到同样的声音，只有两条路：

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 离线渲染（推荐） | 把合成代码抽成公共模块，在 Edge 里用 `OfflineAudioContext` 渲染成 WAV | 音色**完全一致**，比实时快，可批量 |
| B. 移植到 numpy | 用 Python 重写 40 多套音色 | 工作量大，且听感必然不同，弃 |

### 6.2 链路

```
make_video.py ── spec.json ──► tools/export_audio.mjs（Playwright + Edge）
                                   │  打开 web/audio-render.html
                                   │  LPAudio.renderOffline(spec)
                                   │  OfflineAudioContext → AudioBuffer → WAV
                                   ▼
                              _audio.wav ──► ffmpeg 混流 ──► 视频
```

### 6.3 spec 结构

```json
{
  "sampleRate": 44100,
  "duration": 167.6,
  "meter": [4, 4],
  "main": { "instrument": "piano",
            "notes": [{"t": 1.20, "midi": 64, "dur": 0.50}, "…"] },
  "accompaniment": { "instruments": ["cello"], "style": "lyrical", "volume": 0.55 },
  "spatial": {"stereoWidth": 50, "roomSize": 50, "reverbLevel": 35, "mainDistance": 18, "accompanimentDistance": 52}
}
```

- `notes[].t` 直接取视频时间轴（`make_video.py` 已有 `start`，含前奏/lead-in），所以音画天然对齐。
- 伴奏和弦：引擎按 `meter` 把 `notes` 切成小节 → 复用 `addMeasureHarmony()` 推和弦 → 按 `style` 织体铺。
- 采样音色（古筝/竹笛）：渲染前预载 `web/audio/*.wav`；缺失时自动退化为合成音色，不报错。

### 6.4 需要动 `game.js` 的地方

| 位置 | 改动 | 影响 |
|---|---|---|
| `createVoiceAtFrequency()` (2117) | 加 `options.when`，默认仍是 `audioContext.currentTime` | 播放器行为不变 |
| `ensureAudio()` (2018) | 抽出 `buildAudioGraph(context)`，实时/离线共用 | 无 |
| 全局 `audioContext` | 离线时替换为 `OfflineAudioContext` 实例 | 无 |
| `addMeasureHarmony()` | 保持原样，增加"从 notes 造小节"的入口 | 无 |

### 6.5 回退与对照

- `--audio synth` 保留原正弦合成，出问题可一键切回。
- 第一首对照：同一段 20 秒，游戏里录屏 vs 视频音轨，频谱/听感对比。
- 响度：渲染后统一峰值归一到 −1 dBFS，避免视频忽大忽小。
